# CMI backend implementation status

> **Current production checkpoint — 12 November 2026 (verified after source integration and production deployment):**
> - Hosted Supabase project `cgwffpxlwgbnlinzwfoj` now records **15 ordered migrations**: the 3 original foundation migrations plus the 12 CMI domain, authorization, staff lifecycle, first-admin lease and owner-directed safe-default migrations. Migration history versions have been aligned to the exact source migration versions.
> - The hosted database now has **50 public tables**, all 50 with RLS enabled. There are **58 explicit role-capability grants** across the six approved roles (Admin/Pastor 20, Coordinator 11, Team Leader 11, Field Worker 9, Follow-up Volunteer 6, Prayer Intercessor 1). No church, branch or staff records have been provisioned yet.
> - **Nine Edge Functions are ACTIVE**: public-content, staff-session, staff-operations, staff-auth, staff-access-operations, event-operations, announcement-operations, content-operations and calendar-operations. The restricted pastoral-operations function has deliberately not been deployed pending the independent security review required by the decision baseline.
> - GitHub source integration is now consolidated on `main` by merge commit `9c7bb17ff02686f8abfca23d5db2fe62ac7b4cda` (PR #39). The consolidated source includes the bootstrap retry lease, shared request-body limits, the 58-grant safe-default baseline and the updated neutral iOS-inspired login screen. The matching Vercel production deployment is READY at `https://pcg-missions.vercel.app`.
> - The production PWA is READY at `https://pcg-missions.vercel.app`, with Vercel production environment variables for the public Supabase URL and publishable key.
> - Public and authenticated browser roles have no direct SELECT grants on the public tables; business data is intended to flow through verified Edge Functions. The public schema currently has **zero RLS policies**, so direct browser table access remains deny-by-default. Supabase security advisor reports RLS-enabled/no-policy informational findings; this is intentional for the service-role Edge Function architecture, but must remain paired with the server-side authorization boundary.
> - **Still not operationally ready:** Supabase Edge Function secrets have not been configured (transactional email/Resend, bootstrap token and identity, auth HMAC key, contact/follow-up idempotency HMAC keys, and production origin overrides); therefore first-admin provisioning, invitations, password-reset delivery and idempotent writes cannot be verified end-to-end. The Supabase connector available in this session exposes migration/function deployment but not Edge Function secret management.
> - Event registration and transport reservation/capacity transactions, typed ministry reports, full pastoral workflow, export controls, SMS outbox/consent/dispatch, data-retention automation and staging/UAT/backup-restore rehearsal remain incomplete or deliberately disabled. Event/content/calendar Edge Functions currently cover restricted draft operations only; they are not evidence that public registration, transport or SMS dispatch is implemented.
> - Production personal-data use remains gated on church-controller privacy obligations, privacy notice/lawful-purpose confirmation, operational email provider configuration, independent pastoral security review, staging/UAT, restore rehearsal, monitoring and named administrator provisioning.
