The public schema currently has **zero RLS policies**, so direct browser table access remains deny-by-default. Supabase security advisor reports RLS-enabled/no-policy informational findings; this is intentional for the service-role Edge Function architecture, but must remain paired with the server-side authorization boundary.
> - **Authentication configuration is partially verified:** an unauthenticated request to `staff-session` returns the expected `AUTH_REQUIRED` response rather than `SERVICE_NOT_CONFIGURED`, confirming that the function's Supabase URL, service-role key and public key are present. The `staff-auth` password-reset route now resolves correctly after a production route-parser fix (function version 2), but a safe configuration probe returns `AUTH_RECOVERY_NOT_CONFIGURED`; at least one recovery dependency is missing (Resend API key, sender identity, HTTPS app URL, 32+ character auth HMAC key, or administrator notification email list). Bootstrap-specific secrets and contact/follow-up idempotency HMAC keys have not been independently verified. The Supabase connector available in this session does not expose Edge Function secret management.

Event/content/calendar Edge Functions currently cover restricted draft operations only; they are not evidence that public registration, transport or SMS dispatch is implemented.
> - Production personal-data use remains gated on church-controller privacy obligations, privacy notice/lawful-purpose confirmation, operational email provider configuration, independent pastoral security review, staging/UAT, restore rehearsal and monitoring. The initial administrator's password-setup window is currently valid until 13 November 2026 02:14 UTC; actual sign-in and forced password-change completion remain unverified.
