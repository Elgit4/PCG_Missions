## Important distinction: D1 schema replay is not feature completion

The 32 candidate D1 migrations are not a one-to-one conversion of the 29 Supabase migrations. They include legacy Better Auth structures and Transport-related schema that are not part of the current product direction. Migrations `0033`–`0037` address selected gaps discovered during rehearsal, but do not by themselves complete backend parity.

The source Supabase ledger still has 17 migrations applied and 12 pending. Those 12 features remain open until their database structures, Worker operations, authorization and frontend workflows are implemented and tested together.

Specific unresolved items include:
- Team/service-area management audit and equivalent transactional Worker operations.
- Ministry-report submission, review, return and resubmission operations.
- Notification creation on follow-up and event assignment, report review, recipient isolation, read/read-all API operations and duplicate suppression. `staff_notification` is schema-only at present.
- Event-assignment notification timing.
- Assigned-prayer inbox API, assignment-only access and audited narrative reads.
- Staff event registration, cancellation, check-in and event closeout API parity and concurrency tests.
- First-administrator lease acquisition, expiry, release and bootstrap transaction parity. The legacy `staff_admin_bootstrap_state` design is not the Supabase lease model and must not be treated as the production source of truth.
- Private event-flyer storage. Cloudflare R2 is not enabled on the account, so no R2 bucket or upload/download Worker has been created.
- Reimplementation and testing of all 14 Edge Function modules and the 26 PostgreSQL RPC operations identified in `ARCHITECTURE_AND_API_INVENTORY.md`.

## Authentication and frontend status

The current v6 Cloudflare Worker source still imports Better Auth. Its `auth.ts`, `staff-context.ts`, request handler and package dependency have **not** yet been converted to Supabase Auth token verification. The rehearsal database no longer has Better Auth credential/session tables, but this is only a database-side rehearsal change.

The browser API client still builds its business API base as `${SUPABASE_URL}/functions/v1`. The Pages same-origin auth proxy still forwards staff-session and password-lifecycle operations to Supabase Edge Functions. The official frontend remains:

`https://pcg-missions.pages.dev/`

No production Pages environment variable, route, deployment or alias has been changed. No Cloudflare Worker has been deployed from this migration branch.
